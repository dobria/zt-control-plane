# Flow Rules reliability and dependency maintenance

ZT Control Plane `v0.1.3` fixes the Flow Rules template error when enabling
**Ping & traceroute** and includes reviewed dependency updates.

## What changed

- Selecting Ping & traceroute now generates valid rules for both IPv4 ICMP
  and ICMPv6. Previously, the IPv4 rule used a reserved compiler keyword and
  failed with `Missing argument(s) to match`.
- Regression tests cover adding Ping to an empty service allow-list and to
  HTTP/HTTPS, with the Ethernet guardrail enabled and disabled.
- The development dependency `js-yaml` is updated to 4.3.2 for
  [GHSA-2883-xcg3-v3hh](https://github.com/advisories/GHSA-2883-xcg3-v3hh).
- Next.js and its ESLint configuration are updated to 16.3.4, Undici to 8.10.1,
  Lucide React to 1.39.0, tsx to 4.23.13, and React DOM types to 19.2.5.
- Docker Buildx setup is updated to 4.3.0. The optional embedded build uses
  Rust 1.98 and continues to build ZeroTier One 1.16.2.

This release does not require a database migration. Existing saved Flow Rules
are not replaced during an upgrade. To apply the corrected template, select
the desired services and use **Validate & save** after upgrading.

## Upgrade

Back up the persistent `/data` volume, then pull the versioned standard image:

```sh
docker pull ghcr.io/dobria/zt-control-plane:0.1.3
```

The same build is also published to Docker Hub:

```sh
docker pull dobria/zt-control-plane:0.1.3
```

Update the image reference in your deployment and recreate the application
container with the existing `/data` volume. Verify `/api/health`, sign-in,
controller reads, and Flow Rules validation. SQLite state, registered
controllers, encrypted credentials, and user settings stay in the persistent
volume.

Published images support `linux/amd64`. The optional embedded-controller image
is built locally and remains subject to the separate upstream licensing terms.
